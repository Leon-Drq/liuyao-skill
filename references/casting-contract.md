# 六爻起卦数据契约

## 输入格式

推荐使用六组三字符：

HHT, THH, TTT, HHH, HTT, THT

每组从左到右代表三枚钱；H 代表 heads，T 代表 tails。逗号分隔的六组按初爻到上爻排列。

## 规范化映射

| 正面数 | 分数 | 类型 | 阴阳 | 变爻 |
| --- | ---: | --- | --- | --- |
| 3 | 9 | old_yang | 阳 | 是 |
| 2 | 8 | young_yin | 阴 | 否 |
| 1 | 7 | young_yang | 阳 | 否 |
| 0 | 6 | old_yin | 阴 | 是 |

## 结果字段

| 字段 | 说明 |
| --- | --- |
| original_binary | 从上爻到初爻的六位二进制 |
| changing_positions | 变爻位置数组，仍按初爻到上爻 |
| changed_binary | 翻转变爻后的二进制；无变爻时为空 |
| yaos | 6 条爻的标准化结构 |
| payload | 可直接交给 6yao calculate-hexagram API 的请求体 |

## 排盘边界

起卦 skill 不擅自决定：

- 用神；
- 性别分流；
- 六亲；
- 世应；
- 六神；
- 月建、日辰、旬空；
- 卦爻辞或 AI 结论。

这些字段必须由 6yao 的服务端核心和后续解读流程生成。

## 追问边界

同一卦的追问只引用原始 yaos、原始时间和服务端排盘结果，不重新摇卦。若用户换了问题、要求再次确认或改变现实事件，应创建新的六次投掷。
